# 10Pearls_Shine_Assignment3

## Assignment No. 3 – Bug Reporting

This repository contains the deliverables for Assignment 3, focused on bug identification, documentation, and reporting on sample buggy websites.

---

## Learning Objectives

- Understand the bug identification process
- Practice identifying functional defects
- Practice identifying UI/UX defects
- Learn to write clear and structured bug reports
- Understand defect severity and priority
- Document bugs using industry-standard bug reporting formats

---

## Tasks Completed

1. Explored the provided buggy websites
2. Identified defects and unexpected behaviors
3. Documented each bug using a standard bug report format
4. Assigned severity and priority levels
5. Captured clear steps to reproduce
6. Provided expected and actual results
7. Prepared release notes summarizing the identified issues
8. Submitted the Excel sheet through this public Git repository

---

## Detailed Task Breakdown

### Step 1 – Explore the Application
The sample buggy websites were thoroughly explored, testing functionalities such as:
- Navigation
- Forms
- Buttons
- Search functionality
- Input validations
- Page layout
- Links
- Error messages

### Step 2 – Identify Bugs
Bugs were categorized into the following types:

**Functional Bugs**
- Login not working
- Buttons not responding
- Incorrect search results
- Broken links

**UI / Visual Bugs**
- Misaligned elements
- Incorrect fonts or spacing
- Overlapping text
- Inconsistent styling

**Validation Bugs**
- Form accepting invalid inputs
- Missing validation messages

**Usability Issues**
- Confusing navigation
- Poor error messages

### Step 3 – Write Bug Reports
Each bug is documented in the Excel sheet with the following required fields:

| Field | Description |
|---|---|
| Bug ID | Unique identifier for the bug |
| Title / Summary | Short description of the issue |
| Description | Detailed explanation of the defect |
| Steps to Reproduce | Numbered steps to recreate the bug |
| Expected Result | What should happen |
| Actual Result | What actually happens |
| Severity | Impact on the system (Critical/High/Medium/Low) |
| Priority | Urgency of fix (High/Medium/Low) |
| Environment | Browser, OS, device details |
| Status | Current state (Open/In Progress/Closed) |

### Step 4 – Prepare Release Notes
The release notes section summarizes:
- Total bugs reported
- High severity issues
- Major functional problems
- Overall system quality observations
